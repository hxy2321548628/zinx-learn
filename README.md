# zinx-learn

一个循序实现轻量级 TCP 服务器框架的 Go 学习项目。

本项目会参考 2019 年的 [Zinx 网课](https://www.bilibili.com/video/BV1wE411d7th/?spm_id_from=333.788.videopod.episodes&vd_source=848cfd56f5b611313d69d0120f813bfe)理解网络框架的核心思想，但不会逐行照搬当年的实现。在保留课程知识主线的前提下，代码将尽量遵循当前 Go 的开发规范、工具链和设计哲学。

## 学习目标

- 从零理解 TCP 服务器、连接管理、消息封包与路由等核心机制。
- 在实践中理解 Go 的接口、组合、goroutine、channel 和错误处理。
- 学会使用 Go 模块、格式化、静态检查、测试和竞态检测等现代工程工具。
- 记录旧课程实现与当前 Go 实践之间的差异及取舍。

## 实现原则

1. **理解优先**：先理解课程中每个抽象要解决的问题，再编写代码。
2. **简单优先**：优先使用标准库和直接的实现，不为尚未出现的需求过度设计。
3. **惯用 Go 写法**：遵循 `gofmt` 和 Go 的命名、包设计及错误处理惯例，尽量使接口保持小而聚焦。
4. **明确并发边界**：认真处理 goroutine 的生命周期、资源释放、超时、取消和优雅退出。
5. **小步验证**：每个阶段都通过格式化、静态检查和测试后再继续。

> 课程与当前 Go 实践冲突时，优先保留设计意图，并使用当前语言和标准库推荐的方式实现；重要差异会在代码或学习记录中说明。

## 环境要求

- Go 1.25.0（以 [`go.mod`](./go.mod) 中的版本为准）
- Make（可选，也可直接执行对应的 Go 命令）

## 快速开始

```bash
git clone <repository-url>
cd zinx-learn

# 查看所有可用命令
make help

# 执行格式检查、静态检查和测试
make check
```

常用命令：

| 命令 | 作用 |
| --- | --- |
| `make fmt` | 格式化所有 Go 源文件 |
| `make fmt-check` | 检查 Go 源文件是否已格式化，不修改文件 |
| `make vet` | 运行 `go vet ./...` |
| `make test` | 运行全部测试 |
| `make test-race` | 启用竞态检测运行全部测试 |
| `make tidy` | 整理模块依赖 |
| `make tidy-check` | 检查 `go.mod` 和 `go.sum` 是否整洁，不修改文件 |
| `make check` | 运行提交前的完整检查 |

在尚未创建 Go 包的初始化阶段，`vet` 和 `test` 会给出提示并跳过；加入源码后将自动执行实际检查。

## 持续集成与发布

GitHub Actions 会在以下情况运行格式、依赖、静态检查、测试和竞态检测：

- 向任意分支推送提交。
- 创建或更新 Pull Request。
- 推送任意 Git 标签。

当标签对应的检查全部通过后，工作流会自动创建 GitHub Release，并根据自上一个版本以来的变更生成发布说明。当前项目还没有可执行程序，因此 Release 暂时不包含额外二进制附件。

建议使用语义化版本标签：

```bash
# 创建带注释的版本标签
git tag -a v0.1.0 -m "v0.1.0"

# 推送标签后自动触发检查与发布
git push origin v0.1.0
```

如果检查失败，Release 不会被创建。修复后应创建新版本标签，不建议覆盖已推送的标签。

## 开发约定

- 提交前运行 `make check`。
- 新功能应尽量附带测试；并发相关修改应运行 `make test-race`。
- 依赖变更后运行 `make tidy`，并提交 `go.mod` 和 `go.sum`。
- 包名使用简短、有含义的小写单词；导出标识符补充有价值的文档注释。
- 错误应被明确处理或返回，不通过 `panic` 处理普通运行时错误。
